# WordGlance is Firefox-only; the userscript is retired

A userscript fetches from the page, so CORS applies and every replacement endpoint would have to serve `Access-Control-Allow-Origin`. A Firefox background script holding a host permission does not care about CORS at all, and that freedom is what makes the current provider set viable — it is the only reason the undocumented Google endpoint and `freedictionaryapi.com` are both usable here. Supporting both surfaces at once would have forced a materially weaker choice, so the sibling userscript is archived with a pointer back here rather than kept alive against a dying API.

The AMO listing must name every third party that receives the selected word. Add-on policy section 6 is about disclosure, not architecture: there is no rule against embedding a shared API key or against calling an unofficial endpoint, but the extension is expected to say plainly what it sends and where. The unofficial Google endpoint used as a Translation fallback is accepted on the record as a legal risk the author carries — Google's terms prohibit automated access to undocumented endpoints, enforcement is unlikely, and Chrome itself uses the same endpoint. See ADR-0003 for why a keyless primary is the only option left.
